## 1. 目的

「無効化」は、攻撃者が各段階で得たいものを、得られないか、得ても使えない状態にすることである。

検知して追いかける設計は、機械速度の攻撃と競争になる。ARTEX の事例では、標的化から特権到達まで3時間未満、ツールの修正は約55秒である。本書は、競争しないことを第一原則にする。

- 第一手段は不変条件である。変更の commit 前、session の確立前、実行の前に拒否する。拒否は攻撃の速度に依存しない
- 第二手段は無価値化である。盗まれる資格情報、持ち出されるデータ、消されるバックアップを、盗まれても使えない形にしておく
- 第三手段は検知と自動応答である。不変条件で書けない挙動だけを扱う

主体名の判定は遮断の条件にしない。Qilin も ARTEX も、条件の例であって述語ではない。

## 2. 攻撃の分解

### 2.2 ARTEX（Storm-0940）

| 段階 | 公表された内容 | 資料 |
|---|---|---|
| 入口 | バックアップ事業者のマルチテナント application の資格情報を入手。app-only token で顧客テナントへ入る | Microsoft、Huntress 2026 |
| 列挙 | 約1,000テナントへ token 要求を1件ずつ。4本の資格情報で4分以内に200件超のサインイン | Huntress、Microsoft 2026 |
| 永続化 | application へ secret を追加。証明書の追加が失敗すると secret へ切り替え | Huntress 2026 |
| 特権 | service principal が自身に Global Administrator を付与。兄弟の service principal に高権限を付与し、元の service principal を削除 | Huntress 2026 |
| 資格情報 | 複数の Key Vault から secret を一括読み取り | Microsoft 2026 |
| 収集 | Graph によるディレクトリ、メール、SharePoint、Teams へのアクセス。本件での持ち出しは確認されていない | Microsoft 2026 |
| 並行 | 別系統の password spray。成功認証は観測されていない | Microsoft 2026 |

二つの攻撃は入口が違う。Qilin は人の資格情報とオンプレミスのディレクトリ、ARTEX は application の資格情報とクラウドのディレクトリである。共通点は三つある。

1. 正規の資格情報を使う。マルウェアの検知より前に、正規の認証として通る
2. ディレクトリの変更で特権と配布を得る。Qilin は GPO、ARTEX はロール付与である
3. 信頼された管理経路を使う。Qilin は GPO と PsExec、ARTEX はバックアップ事業者の application である

本書の層は、この三点を軸に置く。

各層は、前の層が破られた前提で設計する。L1 を通過した主体は、L2 以降では「正規の資格情報を持つ未知の主体」として扱う。

## 4. L0 露出の縮小

Qilin の入口の一部は、境界機器と業務アプリの脆弱性である。

- インターネットに公開する管理面を棚卸しする。VPN、バックアップの管理面、ERP の管理面を含む
- 管理面は、L1 の条件を満たす経路の後ろに置く。インターネットへ直接出さない
- 悪用が公表された脆弱性は、修正期限を短くする。期限は ※要確認
- 公表前の悪用（SAP の例）は L0 では防げない。L1 以降が前提である

## 5. L2 制御面の不変条件

ここが本書の中心である。両攻撃は、ディレクトリの変更で特権と配布能力を得る。変更そのものを commit 前に拒否すれば、検知の速度は問題にならない。

### 5.1 不変条件

| ID | 不変条件 | 対応する攻撃段階 |
|---|---|---|
| I1a | service principal への secret の追加と、信頼する CA 以外の証明書の追加を、commit 前に拒否する | ARTEX の永続化 |
| I1b | 外部事業者の application は、ロール、所有者、同意、他の application の資格情報を変更できる権限を一つも持たない。拒否ではなく、権限の上限で操作自体をできなくする | ARTEX の特権 |
| I2 | 高権限ロールの付与は、専用の管理経路と、その時間だけ有効な権限を持つ人だけが行える | ARTEX の特権、Qilin の特権 |
| I3a | GPO と SYSVOL を変更できる権限を、常設で持つ account を置かない。Domain Admins の利用は、管理端末とドメインコントローラーからのログオンに限る | Qilin の拡散と展開 |
| I3b | GPO が変更されても、署名の無いログオンスクリプトは業務端末で動かない（L4） | Qilin の拡散と展開 |
| I4 | GPO で配布されたものは、署名済みの App Control 方針が許さない限り実行されない。方針の署名鍵はドメインの外に置く | Qilin の展開 |
| I5a | 一度送り出した監査記録は、送り元の管理者が消せない。送り先はロックした不変ストレージとし、別の信頼領域に置く | Qilin の証跡消去 |
| I5b | 監査の停止と消去は記録に残り、送信の途絶は受け手の側で検出される | Qilin の証跡消去 |
| I6a | バックアップの削除、保持期間の短縮、不変設定と MUA の解除は、別の信頼領域の承認者なしに commit しない | バックアップの破壊 |
| I6b | Entra の高権限ロールは常設のアクティブ割り当てを置かず、承認つきの有効化だけで使う。PIM の外での直接割り当ては拒否できないので、PIM のアラートで検出して取り消す | 単一の盗難資格情報による特権化 |

I1 は `admission-control.md` の P4 と同じである。I3 は同書の節8を具体化する。

製品の機能で commit 前に拒否できるのは、I1a、I5a（記録の削除）、I6a である。I1b、I3a は権限を持たせないことで、I3b と I4 は実行させないことで成り立つ。I5b は検出であり拒否ではない。I6b は有効化にだけ効く。GPO の変更の二人承認は成り立たない。根拠と限界は `precommit-feasibility.md` にある。

### 5.2 管理面の分離

- 制御面（ドメインコントローラー、IdP の管理、バックアップの管理）は、業務端末から到達できない
- 制御面の操作は、専用の管理端末からだけ行う。管理端末は業務のメールとブラウザを使わない
- 常設の高権限アカウントを置かない。権限は時間限定で発行する
- 緊急用アカウントは別に置き、使用を常に通知する

### 5.3 限界

- 管理端末を乗っ取られた場合、I3a は通る。GPO の変更は commit され、I3b と I4 の実行の拒否が残る防御である
- 攻撃者がドメインコントローラーのファイルシステムへ直接書く場合、ディレクトリの commit 前の拒否は効かない。L4 と I5a、I5b で扱う

## 6. L3 資格情報の無価値化

Qilin は Chrome の保存パスワードを収集した。ARTEX は application の secret と Key Vault の secret を使った。盗まれる前提で、盗んでも使えない状態にする。

### 6.1 人の資格情報

- ブラウザへのパスワード保存を、端末の方針で無効にする。保存は専用のパスワード管理ソフトに限る
- 業務で使う SaaS は、IdP の phishing-resistant MFA の後ろに置く。パスワード単独で入れる SaaS を残さない。残る SaaS は台帳で管理する
- パスワード単独で入れる外部サイトは、組織が失効を強制できない。Sophos も同じ指摘をしている。これは L3 の限界として残る
- LSASS の保護など、OS の資格情報保護を有効にする。製品とバージョンは ※要確認

### 6.2 application の資格情報

- 長期の client secret を使わない。証明書、マネージド ID、またはワークロード ID のフェデレーションを使う
- 外部事業者の application は、テナントごとに権限の上限を絞る。照合は application ID で行う
- Key Vault の secret は、読み取る主体を限定する。一括読み取りは連鎖台帳へ入れる
- 外部事業者の application が漏えいしたとき、事業者の再発行を待たずに、自テナント側で無効化できる手順を持つ。application オブジェクトは削除しない（`admission-control.md` 節3.2）

### 6.3 漏えいの先回り

- アクセス仲介者による販売と18日の潜伏は、漏えいから利用までに時間があることを示す
- 外部の漏えい情報（infostealer のログを含む）と自社 account を照合し、一致した資格情報を失効させる。情報源は ※要確認

## 7. L4 実行と横展開の拒否

L2 を通過して配布が行われた場合、配布物が動かない状態にする。

| 対象 | 不変条件 | 対応する攻撃段階 |
|---|---|---|
| サーバー | 許可リストにない実行ファイルとスクリプトは起動しない | 暗号化プログラムの実行 |
| PowerShell | 制約付きの言語モード。署名の無いスクリプトは管理経路以外で動かない | IPScanner.ps1 |
| リモート実行 | PsExec 相当の、管理共有経由のサービス作成を、管理端末以外から拒否する | PsExec による配布 |
| 東西通信 | 業務端末どうしの SMB、RDP、WinRM を拒否する。サーバーへの管理接続は管理端末からだけ | 横展開 |
| WSL | 業務上不要な端末では無効化する。必要な端末では EDR の対象に含める | WSL による回避 |
| 仮想化基盤 | ハイパーバイザーの管理面は制御面と同じ分離にする。署名されたプログラムだけを実行する設定にする。製品とバージョンは ※要確認 | ESXi の暗号化 |

限界。許可リストに入っている正規ツール（PowerShell 本体、管理ツール）を悪用する攻撃は、起動の拒否だけでは止まらない。引数と実行元の条件を連鎖台帳へ入れる。

## 8. L5 データの無価値化

二つの攻撃はどちらもデータの取得を目的に含む。Qilin は公開の脅迫、Storm-0940 はデータ窃取を過去の目的としている。

- サーバーの外向き通信は、既定で拒否する。許可先は台帳で管理する
- 機密データは、ファイル自体を暗号化し、閲覧権限を IdP に結びつける。持ち出されたファイルは、IdP の外では開けない。対象とする製品は ※要確認
- application の Graph 権限は、メール、ファイル、チャットのうち必要なものだけにする。テナント全体の読み取りを、外部事業者に与えない
- Graph の活動ログを有効にする。無い場合、読み取りの有無は「不明」として記録する（`admission-control.md` F12）

限界。暗号化の対象外のデータと、正規の閲覧者が画面から写すデータは、L5 では守れない。公開の脅迫を完全には無効化できない。

## 9. L6 回復の保証

暗号化と破壊は、回復できれば交渉の材料にならない。

### 9.1 バックアップは別の信頼領域に置く

ARTEX の入口は、バックアップ事業者の application だった。Qilin は Veeam の脆弱性を入口にした。バックアップは、守る対象であると同時に入口である。

- バックアップの管理は、本番の IdP とディレクトリから独立した ID で行う。本番の Global Administrator がバックアップを削除できない
- バックアップの削除、保持期間の短縮、暗号化キーの変更は、二人の承認の後に有効になる（I6a）。Azure Backup の Resource Guard、Veeam の four-eyes authorization が該当する。遅延は soft delete の保持期間で近いものを作る。同じものかと、期間の長さは ※要確認
- 少なくとも一つの複製は、書き込み後に変更できない保存先に置く
- バックアップ事業者の application が本番テナントに持つ権限は、バックアップに必要な読み取りに限る。資格情報の追加は I1a で拒否し、ロール付与は I1b の権限の上限で不可能にする
- バックアップ事業者の侵害時に、本番からの接続を切っても、既存の復旧点が残ることを確認する

### 9.2 復旧の訓練

- 復旧は、本番とは別の隔離環境で行える
- 制御面（ディレクトリ、IdP）の復旧を、業務データの復旧より先に置く
- 訓練の頻度と目標時間は ※要確認。訓練していない手順を、復旧できる根拠にしない

### 9.3 DDoS の併用

Qilin は交渉中の DDoS を併用する。公開面の DDoS 対策事業者との事前の取り決めと、交渉の窓口と判断者を事前に決める。

## 10. X 連鎖台帳と応答

`admission-control.md` の連鎖台帳と方針評価を、L2〜L6 の事象へ広げる。台帳は一つである。

### 10.1 追加する事象

`admission-control.md` 節4の action に、次を追加する ※要確認。

| action | 発生源 | 層 |
|---|---|---|
| `gpo_change` | ディレクトリの監査 | L2 |
| `sysvol_write` | ドメインコントローラーのファイル監査 | L2 |
| `audit_disable` | 監査設定とログ転送 | L2 |
| `process_denied` | 実行の許可リスト | L4 |
| `lateral_denied` | 東西通信の拒否 | L4 |
| `secret_bulk_read` | Key Vault の監査 | L3 |
| `egress_denied` | 外向き通信の拒否 | L5 |
| `backup_policy_change` | バックアップの管理監査 | L6 |
| `canary_touch` | おとりのファイルと共有 | L4、L5 |

### 10.2 追加する方針

| ID | 条件 | 応答 |
|---|---|---|
| Q1 | 同じ主体が、`process_denied` または `lateral_denied` を、10分以内 ※要確認 に複数の端末で起こす | その主体の時間限定権限を取り消す。端末を東西通信から隔離する。account はロックしない |
| Q2 | `audit_disable` の要求 | 拒否する。案件を開く |
| Q3 | おとりのファイルまたは共有への書き込み | その端末を東西通信から隔離する。バックアップの遅延削除を延長する |
| Q4 | `backup_policy_change` が、I6a の承認なしに要求された | 拒否する。案件を開く |
| Q5 | `secret_bulk_read` が、登録範囲外の主体から起こる | その主体の token 更新を止める。読まれた secret の再発行を案件にする |
| Q6 | `egress_denied` が、L1 または L2 の拒否と同じ連鎖にある | 連鎖の遮断時間を延長する |

Q1 と Q3 の隔離は、端末単位の東西通信の遮断である。インターネットと IdP への接続は残し、利用者の業務と復旧の連絡経路を止めない。

### 10.3 応答の原則

- 不変条件の拒否（I1a、I2、I4、I5a、I6a、Q2、Q4）は、人の当番を待たない。I1b の設定漏れで commit されたロール付与の取り消しも、人の当番を待たない
- 検知に基づく応答（Q1、Q3、Q5、Q6）は、期限付きで、範囲を連鎖と端末に限る
- account のロックを自動応答にしない。攻撃者に業務停止を誘発される
- ログが無いことを、アクセスが無いことの証拠にしない

## 11. 段階と層の対応

| 攻撃段階 | 第一の無効化 | 第二の無効化 | 残る穴 |
|---|---|---|---|
| Qilin VPN 入口（盗難パスワード） | L1 P1 | L3 漏えい照合 | phishing-resistant MFA の要素自体の窃取 |
| Qilin 脆弱性入口 | L0 | L4 実行の拒否 | 公表前の悪用 |
| Qilin DC への移動 | L2 管理面の分離 | L4 東西通信 | 管理端末の侵害 |
| Qilin GPO ログオンスクリプト | L2 I3a | L4 署名の無いスクリプトの拒否（I3b） | 管理端末の侵害。許可リストにある実行ファイルの悪用 |
| Qilin Chrome 資格情報 | L3 ブラウザ保存の無効化 | L1 で再利用を拒否 | パスワード単独の外部サイト |
| Qilin ログ消去 | L2 I5a | I5b の途絶の検出 | 転送前に消された端末ログ。送信エージェントを止められた後の事象 |
| Qilin PsExec 配布 | L4 リモート実行の拒否 | Q1 | 許可された管理ツールの悪用 |
| Qilin WSL 回避 | L4 WSL の無効化 | EDR の対象拡大 | WSL が必要な端末 |

## 13. 作業順

`admission-control.md` 節11の後に続ける。

1. 製品とバージョンを固定する。I1〜I6 の文書調査は `precommit-feasibility.md` で済んだ
2. L6 を先に置く。他の層が全部破られても回復できる状態を、最初に作る。実証は G9、G10、G13、G14
3. L2 の I1a〜I5b と I6b を入れる。実証は G1、G2、G6、G15、G16
4. L3 を入れる。実証は G7、G8
5. L4 を入れる。実証は G3、G4、G5、G11
6. L5 を入れる。実証は G12
7. L0 の棚卸しを定例にする

L6 を先にする理由は、他の層の設定を誤ったとき、業務を戻す手段になるからである。

### 13.1 実装

連鎖台帳、方針評価（P1〜P8、Q1〜Q8、I5b）、Entra の収集と強制は、`service/` と `deploy/` に実装した。Kubernetes と OpenShift の両方へ kustomize で配置する。構成と未実証の点は `README.md` にある。強制は既定で dry-run であり、検証環境での F6、G16 の実証の後に切り替える。
